# REA 与手工阅读的取舍（web-mobile 实测）

日期：2026-11-14
样本：`targets\web-mobile`（Cocos Creator 2.x 网页包，3.8 MB，游戏逻辑 7.2 KB / 一行压缩）

## 实测数据

| 指标 | REA | 手工阅读 |
|---|---|---|
| 耗时 | 数分钟（含起 worker、解析 592k AST 节点） | 十几分钟（读 7.2 KB + 场景 json） |
| 产出 | 48.8 MB Evidence | 一份 400 行报告 |
| 是否还原玩法 | ❌ 未给出规则 | ✅ 完整 |
| 是否识别模块结构 | ❌ `modules = 0` | ✅ 5 个组件 |
| 否定性结论（无存档/无联网） | ✅ 可仲裁、带证据 | ⚠️ 靠 grep，可信度略低 |
| 中文日志字符串 | ✅ 全捕获 | ✅ |
| 属性级读写（`hp`/`score`） | ✅ 22k 语义节点 | ✅ |

## 什么时候用 REA

- 目标大到读不完：压缩后的 1 MB+ 单文件 bundle、Electron 的 `app.asar`
- 需要**可对外的证据链**：每条结论带文件 + 行列位置 + sha256
- 需要否定性结论：确认「没有网络请求」「没有本地存储」「没有 IPC」
- 需要跨文件图：306 个 `require` 里哪些能解析、哪些解析不了

## 什么时候直接读

- 代码总量小（< 50 KB）且未混淆 —— 本次就是，7.2 KB
- 需要回答「玩法是什么」「数值多少」这类**语义问题**，工具的图和语义节点不构成答案
- 目标是老框架（Cocos 2.x `__require`、RequireJS、自家模块表），REA 的模块识别不覆盖

## 已知坑

1. **PowerShell 重定向会破坏输出**：`rea ... --json > file` 经 PowerShell 会按 GBK 转码，
   UTF-8 的 `"到9了"` 变成非法字节，JSON 直接解析失败。必须用 `cmd /c`。
2. **完整 Evidence 不要进上下文**：48.8 MB。用 `--format md` 或 `--filter-output`。
3. **Evidence 体积与目标不成比例**：3.8 MB 目标 → 48.8 MB 输出，压缩引擎贡献 87% 的节点。
